Isocast 0.0.11 for Apple-silicon Macs (macOS 14+), Linux and, for the first time, Windows 10 and 11 (x64). If you're on 0.0.10 on a Mac, Isocast › Check for Updates… installs it. Your permissions carry over.

**Isocast on Windows (new)**
- **Install:** download `Isocast-0.0.11-windows-x64-setup.exe` from the release and run it. It installs for your user only, with no administrator prompt, and needs Windows 10 22H2 or later on x64. Settings › General › Check for Updates finds later versions; Isocast doesn't check on its own, so no update prompt lands in a recording.
- **Record like on a Mac:** screens and single windows, cameras, microphones, desktop audio and the sound of individual apps, media files (decoded on the GPU), web pages (through Microsoft Edge WebView2), text and images, each as its own ISO file beside the program. Files are written so a crash keeps what reached the disk.
- **Encoding on NVIDIA and everything else:** NVENC records H.264 and HEVC, including 10-bit HEVC (tested on an RTX 5070); without NVENC, Isocast uses Media Foundation's hardware or software encoders. Every encoder is tested before a take opens any file, including a check that its picture decodes correctly (an encoder that turns out green or black is skipped), and Settings › Recording names the one in use and why.
- **Each recording and stream gets its own size:** a 4K canvas can record at 4K and stream at 1080p at the same time.
- **Streaming** to RTMP and RTMPS services, live previews, audio monitoring, OBS import (recording to your Videos folder) and Help › Report a Bug…, as on the Mac.
- **Desktop audio leaves out Isocast's own monitoring,** and app sound and filtered desktop sound follow your output device's clock, so they stay in time with the picture over long takes and when you switch the default output.
- **Recordings keep going when something breaks:** if the hardware encoder fails mid-take, Isocast restarts it and carries on in the same file from the next keyframe (or in a second file beside it, if the restarted encoder needs different settings; sound keeps recording while the second file opens, and a problem closing the first file doesn't stop the second). If the screen or window capture helper crashes, the source comes back on the same window or screen, within a few seconds, and never on another window with the same title. `isocast status` and the take's manifest say what was lost and for how long, and list only files that hold a picture.
- **Global hotkeys and push-to-talk** work while another app is focused, and Settings › Hotkeys records new chords.
- **Settings › Diagnostics and `isocast doctor`** show which graphics card captures, draws and encodes.
- **Follows Windows' "Show animations" setting.**
- **The first web page source waits for WebView2 to start** (up to 35 seconds on a cold start) and says "starting the web engine" meanwhile, instead of failing.
- **Uninstalling** waits for files that are briefly in use instead of failing.
- **Graphics drivers that fail Isocast's first test draw** get a second try with Microsoft's newer shader compiler, which ships with Isocast, so the program doesn't stay black.

**On Linux**
- **More ways to install:** the tarball is now built on Debian 12, so it runs on x86-64 and arm64 distros with glibc 2.36 or later, and its installer names any missing libraries. Arch and Fedora can build native packages from the PKGBUILD and RPM spec in `packaging/`. Thanks to **alerque**, who maintains the AUR package.
- **Global hotkeys** work while another app is focused, through the desktop's GlobalShortcuts portal; your desktop may ask you to confirm them. Thanks to **Mateusz Tymek** ([#303](https://github.com/anomalyco/isocast/pull/303)).
- **Install as a recording engine on a server:** `./install.sh --engine-only` from the tarball installs just `isocast` and `isocastd` (with their helpers), without the app or desktop libraries, for control from another computer.
- **Uses your distro's OpenH264** (version 2.6 or later) when Cisco's download isn't installed. Thanks to **alerque** for reporting it ([#230](https://github.com/anomalyco/isocast/issues/230)).
- **H.264 OFF in the status bar** when no OpenH264 is found, with **Download OpenH264** (or the command to copy) there and wherever a start or Go Live is refused for it, not only in first run.
- **X11 without a desktop portal:** screens and single windows are captured directly, and Isocast asks which screen to record in a small window of its own, naming each one ("HDMI-1 · 1920×1080 · primary").
- **Screen capture works on desktops that share screens as DMA-BUF,** including tiled buffers from the GPU Isocast draws on.
- **Desktop audio leaves out Isocast's own monitoring.**
- **PipeWire is optional:** without it, Isocast still starts, records test patterns, media files and cameras, and `isocast doctor` says what's missing.
- **Media files decode in a separate helper,** so a crashing or stuck decoder ends only that source, not the recording. The helper starts faster, and Stop measures files without waiting for it.
- **Follows the desktop's reduce-motion setting.**
- **A screen or window source that's waiting for you to choose** shows a grey clock instead of a red failure badge, and its Properties offer "Choose a screen…" instead of an error. Clearer wording in first run, the Display and Window pickers and the Virtual Camera popover.
- **Stream keys and remote-engine secrets go in the desktop keyring** (such as GNOME Keyring or KWallet) when one is available, instead of a file. Servers without one keep the owner-only file. Thanks to **Mateusz Tymek** ([#321](https://github.com/anomalyco/isocast/pull/321)).
- **Bug reports include Isocast's crash records** from `coredumpctl`, trimmed to fields that are safe to share, and developer mode shows memory use. Thanks to **Mateusz Tymek** ([#318](https://github.com/anomalyco/isocast/pull/318)).
- The virtual camera no longer copies each frame before converting it.

**On every platform**
- **Settings › Diagnostics** lists every `isocast doctor` check in plain words, grouped by capture, encoding, audio, disk and engine, with what to do about warnings, plus Copy and Report a Bug….
- **Sources with a problem get a warning badge** in the Sources dock, with a tooltip that says what's wrong.
- **After a crash, "Recovered your last recording"** says how many files were kept, how long they are and where, with Show in Finder or Explorer and Report a Bug…. If an ISO ends early during a take, Isocast says which one and that the rest keep recording.
- **Properties and Filters say why the live picture is missing,** for example when previews are paused or the engine isn't answering.
- **Report a Bug… is offered where things fail:** a refused start, a stopped or failed recording and the "can't reach its engine" screen. If sending fails, Retry Send sends the same report, and the private zip is never steered into a public issue.
- **After an update, the app and CLI switch to the newly installed engine** once it's idle, never in the middle of a take.
- **Plainer wording** in first run, errors and warnings, with titles that say what happened instead of "Warning".
- **Web page sound stays in time with the picture:** its timing comes from the page's own clock, so short pauses keep their length, and sound and picture line up within about one frame.
- **Screen readers reach the Details links** in Properties and Settings › Diagnostics.
- **Settings › General no longer shows a Calibrate button that can't work** on Windows and Linux.
- An audio gap is counted once on an ISO track, not twice.
- `isocastd --version` and `--help` print and exit without starting an engine.

**Known limits**
- **Windows:** these still need a check on a real desktop: global hotkeys while another app is focused, push-to-talk release, chord conflicts and rebinding, and window capture recovery. Laptops with two graphics cards, and Intel and AMD graphics, aren't tested yet.
- **Windows:** sound played to an output that isn't your default drifts against the picture in filtered desktop audio (about 50 ms over 20 minutes when the two devices' clocks differ). Isocast warns when it happens; record that app with Application Audio, or turn off monitoring, to avoid it.
- **Windows:** desktop audio can exclude only an app that started Isocast or that Isocast started; record the apps you want with Application Audio instead. Monitoring can't be turned on while unfiltered desktop audio is recording.
- **Windows:** the virtual camera and Final Cut and Premiere XML export aren't available yet (OpenTimelineIO export is), and the replay buffer is untested. There's no Arm64 build.
- **Linux:** global hotkeys are tested on Hyprland; GNOME and KDE still need a check on a live desktop.
- **Windows and Linux:** calibration isn't available, so Isocast uses its built-in encoder estimates; Automatic Quality still adapts while recording.
- **Windows:** carrying on after the graphics card resets mid-take, keeping the recording, stream and previews going, is off by default while it's tested on real hardware; set `ISOCAST_ENABLE_LIVE_GPU_RECOVERY=1` before the engine starts to turn it on. Scenes with cameras, web pages, media files, images or text aren't recovered and keep recording as before.
- **Web page sound and picture** were lined up on an M2 Mac, an RTX 5070 Windows PC and a Linux VM; other computers and audio devices may land a little further apart.
- **Linux:** there are no automatic updates, and Debian 12 still needs PipeWire 1.0.5 or later from bookworm-backports for screen and audio capture.
