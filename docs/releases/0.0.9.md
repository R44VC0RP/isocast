Isocast 0.0.9 for Apple-silicon Macs (macOS 14+). If you're on 0.0.8, Isocast › Check for Updates… installs it. Your permissions carry over.

**A recorder, with takes that go to your editor**
- **The in-app editor is gone:** the Editor window, timelines, recording targets and `.isoprj` project files are removed, so Isocast stays a recorder. Your recordings are unchanged, and older project files stay on disk untouched; Isocast just no longer opens them.
- **Export a take for your editor:** `isocast project export-nle --format fcpxml|xmeml|otio` writes a take as a Final Cut Pro, Premiere Pro (DaVinci Resolve with `--app resolve`) or OpenTimelineIO project, with every ISO source on its own track and the program on top, lined up from the take's session file, with its markers. It points at your original files, so nothing is re-encoded or copied. Agents use the MCP tool `export_take_nle`.

**Control Isocast on another Mac (early)**
- **Settings › Remote** has two switches, both off: **Control Other Computers** and **Let Other Computers Control This One**. Pair once with a code, then pick the engine in the engine menu (bottom left); it opens in a window of its own.
- **The program plays as live video**, with WebRTC sound once you turn on the program monitor's speaker (off by default to avoid an echo).
- **Remote viewing does less CPU work:** resizing reuses its GPU setup between pictures, and decoded video stays on the Mac's GPU instead of being copied through CPU images. Remote and local pictures use the same colour handling.
- **Sound recovers from lost network packets** without waiting through a long gap. Remote video also supports clients that need H.264 Constrained Baseline; recording quality and profiles are unchanged.
- Pair on your local network or over Tailscale, with each side's identity pinned when you pair. Both computers need the same Isocast version. The `isocast` command and MCP reach a paired engine with `--engine`.

**Screen colour depth**
- **Settings › Recording › ISO Recording › Screen / ISO Colour Depth:** 8-bit (the default, smaller files) or 10-bit HEVC (smoother gradients, more CPU and about 40% larger screen files). This sets the depth for all ISO files; a source's Properties can override it.
- 10-bit HEVC screen files keep the screen's colours instead of shifting in tone.

**Behind the scenes**
- **Previews give recordings priority:** on a busy Mac with a 30 fps canvas, previews step down to 15 fps sooner. Engines using software graphics pause previews during recording or streaming and resume afterward.
- `isocast api spec --json` describes every engine method as an OpenRPC document, the contract the app, the `isocast` command and MCP all use.
- **A like-for-like comparison with OBS:** both apps recorded the same synthetic 1080p60 program plus one 1080p60 ISO file (OBS Studio 32.2.2 with the Source Record plugin; HEVC, no B-frames, AAC 256 kb/s) on a MacBook Pro with M4 Max. A development build from 22 October used 43.8% of one core and 208 MiB, OBS 97.2% and 1,192 MiB, both writing every frame (median of 3 interleaved runs, VideoToolbox encoding included). It is not a measurement of this exact build.
