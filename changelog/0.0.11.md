## Major
### Isocast on Windows
The first Windows release: a per-user installer for Windows 10 22H2 and later (x64) with no administrator prompt. It records screens, single windows, cameras, microphones, desktop audio, app sound, media files and web pages, each to its own ISO file, encodes with NVENC (H.264, HEVC and 10-bit HEVC) or Media Foundation, and streams over RTMP. A failed encoder or capture helper restarts mid-take without ending the recording. The virtual camera and Final Cut and Premiere XML export aren't available on Windows yet, and updates are manual checks.

### Settings › Diagnostics
A new page lists every `isocast doctor` check in plain words, grouped by capture, encoding, audio, disk and engine, with what to do about each warning. Settings › Recording names the encoder actually in use, and a source with a problem gets a warning badge in the Sources dock.

## Improvements
- After a crash, "Recovered your last recording" says how many files were kept, how long they are and where. If an ISO ends early during a take, Isocast says which one.
- Report a Bug… is offered where things fail, and Retry Send keeps the private report zip out of public issues.
- Properties and Filters say why the live picture is missing.
- After an update, the app and CLI switch to the newly installed engine once it's idle, never mid-take.
- First run, errors and warnings use plainer words, and warnings have titles that say what happened.
- On Windows, each recording and stream is scaled to its own size, desktop audio leaves out Isocast's own monitoring, and app sound stays in time over long takes.
- On Windows, global hotkeys and push-to-talk work while another app is focused, and Isocast follows the "Show animations" setting.
- On Linux, global hotkeys work while another app is focused, through the desktop's GlobalShortcuts portal. Thanks to Mateusz Tymek.
- On Linux, `./install.sh --engine-only` installs the tarball as a headless recording engine for a server.
- On Linux, a screen or window source waiting to be chosen shows a grey clock and a Choose button instead of an error.
- On Linux, stream keys and remote-engine secrets go in the desktop keyring when one is available. Thanks to Mateusz Tymek.
- On Linux, bug reports include Isocast's crash records, and developer mode shows memory use. Thanks to Mateusz Tymek.
- On Linux, screens shared as tiled DMA-BUF from the same GPU are captured.
- Web page sound takes its timing from the page's clock and lines up with the picture within about one frame.
- Screen readers reach the Details links in Properties and Diagnostics.
- On Linux, Isocast uses the distro's OpenH264 2.6 or later when Cisco's isn't installed. Thanks to alerque for reporting it.
- On Linux, the status bar shows H.264 OFF with a Download OpenH264 action whenever the codec is missing.
- On Linux under X11 without a desktop portal, screens and single windows are captured directly.
- On Linux, screens shared as DMA-BUF are captured, desktop audio leaves out Isocast's own monitoring, PipeWire is optional, and Isocast follows the reduce-motion setting.
- The Linux tarball is built on Debian 12 and runs on distros with glibc 2.36 or later; Arch and Fedora can build native packages from `packaging/`.
- On Linux, media files decode in a separate helper, so a crashing decoder ends only that source.
## Fixes
- An audio gap is counted once on an ISO track.
- On Windows, an encoder whose test picture decodes wrong (green or black) is skipped before the take starts.
- On Windows, sound keeps recording while a second file part opens, and a problem closing the first part doesn't stop the second.
- Uninstalling on Windows waits for files that are briefly in use.
- On Windows and Linux, Settings › General no longer shows a Calibrate button that can't work.
- On Linux, media helpers start faster and Stop measures files without waiting for them.
- The first Windows web page source waits for WebView2 to start instead of failing.
- On Windows, a take's manifest no longer lists a second file part that never received a picture.
- `isocastd --version` and `--help` print and exit without starting an engine.
